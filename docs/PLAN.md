# Sonar v2 — план

Источник правды для разработки. Решения здесь уже приняты; менять — только через владельца проекта.

## 1. Цель версии 1

Sonar сам находит компании в Google Maps, собирает контакты (сайт, ЄДР, Prozorro, соцсети), оценивает их,
пишет первым через лучший канал и ведёт переписку с помощью ИИ. Деньги и договоры — человеку. Всё видно в CRM.
Ниша, страна и услуга настраиваются; тестовый пример — Украина + авто.

Версия 1 готова, когда в CRM можно:
- создать кампанию (страна, города, запросы, предложение, каналы, бюджет);
- запустить порцию 20/50 компаний и видеть прогресс каждого этапа;
- открыть карточку компании: контакты с источниками, ЄДР, соцсети, скоринг, описание от ИИ;
- отправлять через email, Telegram, WhatsApp и формы с лимитами аккаунтов (режимы: авто / после одобрения / вручную);
- получать ответы во «Вхідні»: ИИ отвечает, деньги и договоры уходят человеку, отказ навсегда останавливает контакт;
- везде, где человек пишет или настраивает, пользоваться ИИ-помощником;
- видеть расходы по сервисам; при достижении месячного бюджета платные задачи останавливаются;
- работать на украинском, в светлой и тёмной теме.

Не входит: переписка в Instagram/Facebook/LinkedIn (только публичные данные без входа), отправка в Viber, роли пользователей.

## 2. Архитектура

| Контейнер | Что делает |
| --- | --- |
| `web` | Next.js: страницы CRM, API, вебхуки (Resend, WAHA) |
| `worker` | очередь pg-boss: все этапы конвейера, лимиты, повторы, Playwright |
| `postgres` | Postgres 17, две базы: `sonar` (наша) и `registry` (ЄДР, уже заполнена) |
| `waha` | WhatsApp HTTP API, сессия на номер |

Внешние сервисы: Google Places API (New), OpenRouter, Resend, Telegram (GramJS, аккаунты команды), WAHA, 2captcha, IPRoyal (прокси), Prozorro public API.

**База `registry`** — существующий том `sonar-server_postgres` старого Sonar (Postgres 17). Таблицы: `edr_legal_entities` (2.02 млн),
`edr_fops` (7.07 млн), `edr_founders` (6.55 млн), `edr_public_organizations`, `edr_branches`, а также `edr_contacts` / `edr_contact_sources`
(контакты, найденные старым обогащением, с источниками). Sonar только читает её.
Схема — `docs/registry-schema.sql`. Поиск: по `edrpou` (btree), по названию — `normalized_name` (gin_trgm и md5-индекс точного совпадения).
Подробности записи (адрес по частям, КВЕД и т.д.) — в `raw_payload` jsonb. Таблицы-заготовки старого импортёра в схему не включены.

## 3. Конвейер обработки компании

Каждый этап — задача в очереди. Ошибка этапа не останавливает остальные.

1. **Google Maps.** Text Search (New) по запросам кампании, страницы по 20, field mask. Дубли — по `place_id`.
   Хранение: `place_id` бессрочно, остальные поля Google — 365 дней с автообновлением (срок в настройках).
2. **Сайт.** Главная, контакты, «о нас», реквизиты, подвал, sitemap; глубже — пока не найдены контакты или не достигнут потолок из настроек.
   fetch, при пустой странице — Playwright. Извлекаем: почты (вкл. «[at]»), телефоны (E.164), ссылки на мессенджеры и соцсети,
   schema.org, формы и тип капчи, регистрационные коды. Ничего не нашли → ИИ-разбор сайта дешёвой моделью с лимитом цены.
   robots.txt и защиту от ботов не обходим → статус «сайт недоступен» с причиной.
3. **Реестры.** Украина: `registry` (по коду; без кода — по названию + адресу) и Prozorro (контакты поставщиков из тендеров).
   Другие страны — отдельные адаптеры позже.
4. **Соцсети и мессенджеры.** Публичные данные профилей (подписчики, последний пост). Есть ли WhatsApp/Telegram у номера —
   через аккаунты команды в их лимитах.
5. **ИИ-анализ и скоринг.** Скоринг = сумма баллов по весам кампании (код). Дешёвая модель: описание, топ контактов по категориям,
   черновик первого сообщения на языке компании. Только для компаний выше порога.
6. **Отправка.** Лучший канал из включённых. Режимы: авто / одобрение / вручную. Очередь на аккаунт: дневной лимит, случайные паузы,
   рабочие часы по часовому поясу компании, прогрев. Капча → 2captcha (если включено) или ручная очередь.
7. **Диалог.** ИИ классифицирует входящее: интерес, вопрос, цена/оплата, договор, жалоба, отказ, автоответ.
   По правилам отвечает сам или ставит в «Потрібна людина». Отказ → `do_not_contact`.

Статусы задачи: queued · running · done · skipped (причина) · failed (причина + «Повторити») · paused.
Статусы компании: new → enriching → ready → contacted → replied → interested → deal; или refused / do_not_contact.
Статусы сообщения: draft → awaiting_approval → queued → sent → delivered → read; или failed.

## 4. Модель данных (база `sonar`)

campaigns, batches, companies (уник. по place_id / домену / рег. коду), contacts (тип, значение, источник, проверен, ранг),
company_facts (источник, expires_at), analyses, tasks (читаемый статус для CRM; очередь — pg-boss), channel_accounts,
conversations, messages, handoffs, do_not_contact, templates, prompts, handoff_rules, settings, services, spend_events, users.
Точные поля — в задачах, через миграции Drizzle.

## 5. CRM: страницы и внешний вид

Меню слева (на телефоне — сверху): **Огляд, Кампанії, Компанії, Вхідні, Канали, Фінанси**, внизу — Налаштування.

| Страница | Содержание |
| --- | --- |
| Огляд | показатели (компании, с контактами, отправлено, ответили, расходы), «Зараз у роботі» — этапы порции с прогрессом и статусом, «Потрібна людина», «Помилки та паузи» с кнопкой, воронка за 30 дней |
| Кампанії | список кампаний слева; справа настройки: страна, города, запросы (чипы), размер порции, лимит расходов, предложение, каналы, режим отправки, веса скоринга (ползунки); список порций |
| Компанії | фильтры, вкладки по статусу, таблица: компания, скоринг (число + полоска), лучший канал, контакты, ЄДР, статус, последнее действие |
| Картка компанії | шапка с действиями, скоринг с разбивкой, описание ИИ, топ контактов по категориям с источником, история, ЄДР, соцсети, источники данных |
| Вхідні | список диалогов с вкладками, переписка, баннер «ІІ зупинився: …», черновик ИИ с кнопками, правила передачи человеку |
| Канали | по каналам: аккаунт, владелец, «сьогодні / ліміт», следующая отправка, состояние, действие; правила отправки |
| Фінанси | бюджет месяца, расходы по дням, таблица сервисов с тарифом, использованием, суммой, состоянием |
| Налаштування | правила передачи человеку, шаблоны, промпты, пользователи, сроки хранения |

## 7. Сервер

Ubuntu 22.04, 8 ядер, 15 ГБ RAM, ~43 ГБ свободно. Docker 29 + Compose. На сервере есть другие проекты — трогать только своё.
Новый Sonar: `/opt/sonar-v2`, порты только на 127.0.0.1, снаружи — nginx + HTTPS на `sonar.cryid.com`.
Старый Sonar остановлен, кроме его Postgres (он станет `postgres` нового Sonar). Данные старого Sonar без ЄДР: `/root/old_sonar_without_edr.dump`.
Бэкап: ежедневный pg_dump базы `sonar`, 7 последних.

## 8. Решения после обсуждения (11.11.2026)

Приоритет — **весь функционал работает целиком**. Юридические ограничения, прогрев аккаунтов и тонкая настройка — после версии 1.
Лимиты отправки остаются настраиваемыми, стоп по отказу (`do_not_contact`) — обязателен.

| Тема | Решение |
| --- | --- |
| Успех версии 1 | свободная переписка во всех каналах: все функции работают, контакты проходят без сбоев |
| Telegram | сначала импорт номера в контакты; ошибка, приватность или PEER_FLOOD → пометка на контакте («Telegram недоступний: причина»), идём дальше |
| Google Places | жёсткий лимит **в деньгах** (кампания и месяц). Набор полей — «профили запроса» в настройках с ценой каждого, чтобы пробовать разные; поле сайта запрашивается всегда |
| Уведомления | пока только красные точки-счётчики в CRM (Вхідні, «Потрібна людина», ошибки) |
| Команда | кампании общие; журнал действий `activity_log`: кто, что, с чем, когда — видно в карточках и на отдельной вкладке |
| База знаний ИИ | пока тестовая заглушка FAQ; цены и обещания ИИ сам не даёт — передаёт человеку |
| Звонки | последним этапом; пока список «кому можно позвонить» с номерами, без реальных звонков |
| Язык | определяется автоматически по сайту, Google и стране; ИИ пишет и отвечает на языке компании |
| ЄДР | доступ только из Sonar; API для других проектов — позже |
| Mac mini | остаётся: место для бэкапов и локальная разработка |
| Старые данные | не нужны; из старого проекта берём только ЄДР |
| Защита ИИ | входящий текст — данные, не инструкции; максимум N ответов ИИ подряд без живого ответа (защита от автоответчиков) |

Проверить до шага 5: WAHA Core держит одну сессию на контейнер — для нескольких номеров нужна WAHA Plus или несколько контейнеров.
