# Правила для агента (Sol)

Sonar — CRM, которая находит компании, собирает контакты, оценивает их и ведёт переписку с помощью ИИ.
Полный план: `docs/PLAN.md`. Задачи приходят промптами из `docs/prompts/`. Делай только то, что в задаче.

## Стек (не менять без согласования)
- TypeScript везде, Node 22, pnpm workspaces.
- `apps/web` — Next.js 15 (App Router), Tailwind v4, shadcn/ui, next-themes.
- `apps/worker` — Node-воркер, очередь pg-boss, Playwright (когда понадобится).
- `packages/db` — Drizzle ORM: схема и миграции базы `sonar`, read-only клиент базы `registry` (ЄДР).
- `packages/core` — общая логика без зависимостей от фреймворков (телефоны, скоринг, бюджет, типы).
- Один Postgres 17 с двумя базами: `sonar` (наша) и `registry` (ЄДР, только чтение). Docker Compose.

## Как работаем
1. Одна задача = одна ветка = один Pull Request, до ~400 строк изменений (миграции и lock-файлы не считаются).
2. В описании PR: что сделано, как проверить, что не сделано. Без отчётов и новых документов.
3. Новые сервисы, библиотеки, таблицы, страницы — только если они названы в задаче. Сомневаешься — спроси в PR.
4. Тесты (Vitest) — на логику: извлечение контактов, телефоны, скоринг, лимиты, бюджет. Не на вёрстку.
5. Перед PR: `pnpm lint && pnpm typecheck && pnpm test` проходят.

## Правила кода
- Тексты интерфейса — на украинском, только через словарь `apps/web/src/i18n/uk.ts`. Код, имена, комментарии — на английском.
- Настройки (лимиты, сроки, промпты, веса) — в базе, не константами в коде.
- Каждая внешняя операция — задача в очереди со статусом: queued, running, done, skipped, failed, paused. У failed и skipped — понятная причина на украинском.
- Повтор задачи не создаёт дублей и не отправляет сообщение второй раз (ключ идемпотентности).
- Платный запрос: сначала проверить бюджет, потом выполнить, потом записать фактическую цену в `spend_events`.
- У каждого найденного факта — источник и дата.
- Никакой привязки к одной стране: телефоны через libphonenumber-js в E.164, страна по умолчанию — из кампании.
- Любое поле, где человек пишет текст или настраивает что-то, получает ИИ-помощника (компонент `AiAssist`, дешёвая модель).
- Отказ компании — в `do_not_contact`, проверка перед каждой отправкой во всех каналах.

## Нельзя
- Коммитить секреты. Только `.env.example` с пустыми значениями.
- Реальные отправки и платные запросы в тестах — только заглушки.
- Писать в базу `registry` (кроме отдельного импорта ЄДР, когда он будет в задаче).
- Обходить robots.txt, защиту от ботов и лимиты платформ.
- Менять дизайн-токены и структуру меню без задачи. Образец — макет (описание в `docs/PLAN.md`).
